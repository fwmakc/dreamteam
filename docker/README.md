# Контейнеры с моделями

Здесь живут модели для инструментов агентов `look` (зрение) и `image`
(генерация картинок). Папка **самодостаточна** — приложение о ней ничего не
знает. Скопируйте её на машину с моделями (хоть на эту же, хоть на сервер в
локалке) и поднимите нужные модели — каждый профиль назван именем модели:

```
docker compose --profile qwen2-vl-2b --profile sd-turbo up -d
```

Первый старт скачивает модели с Hugging Face в named volume — запаситесь
местом и терпением. Проверка, что поднялось (порт смотрите в таблице):

```
curl http://localhost:8000/v1/models   # зрение (llama.cpp или vLLM)
curl http://localhost:8100/health      # картинки (facade): {"models":[...],"device":"cpu"}
```

## Модели

| Профиль = модель | Что умеет | Порт | Железо |
| --- | --- | --- | --- |
| `qwen2-vl-2b` | зрение, CPU | 8000 | без GPU, ~3 ГБ RAM |
| `qwen3-vl-4b` | зрение посвежее, CPU | 8003 | без GPU, ~5 ГБ RAM |
| `qwen2.5-vl-7b` | зрение, GPU (vLLM) | 8001 | ~16 ГБ VRAM |
| `qwen3-vl-8b` | зрение, новее и точнее (vLLM) | 8002 | ~20 ГБ VRAM |
| `sd-turbo` | генерация, CPU | 8100 | без GPU, ~6 ГБ RAM |
| `bk-sdm` | лёгкая генерация с LCM (4–8 шагов), черновое качество, CPU | 8105 | без GPU, ~3 ГБ RAM |
| `flux-schnell` | быстрая генерация, Apache-2.0 | 8101 | ~16 ГБ VRAM |
| `flux-dev` | качественная генерация (gated) | 8102 | ~16 ГБ VRAM |
| `photomaker` | **контроль лиц**: фото человека в refs → рисует его | 8103 | ~12 ГБ VRAM |
| `qwen-image-edit` | перерисовка по нескольким референсам | 8104 | ~40 ГБ VRAM |

CPU-связка для совсем слабой машины — `qwen2-vl-2b` + `bk-sdm`, суммарно
~6 ГБ RAM: весь цикл «сгенерировал → сохранил → посмотрел глазами»
проверяется целиком. Смысл `bk-sdm` — память, а не красота: его UNet втрое
меньше sd-turbo (пайплайн влезает в ~4 ГБ ОЗУ), а LCM-адаптер сокращает
генерацию до нескольких шагов, так что по скорости он уже сопоставим с
sd-turbo. Если ОЗУ побольше (от ~10 ГБ), берите `sd-turbo` — качество
заметно выше. GPU-модели любые комбинации: профили независимы, у каждой
свой порт — можно держать поднятыми несколько сразу.

**Контроль лиц.** `photomaker` — PhotoMaker V2 поверх фотореалистичного
RealVisXL (взят именно он, а не PuLID/InstantID, потому что он нативно
поддержан в diffusers и не тянет сторонние репозитории, insightface и
ControlNet). Агент передаёт 1–3 фото человека как `refs` — модель встраивает
его лицо в любую сцену по промпту. База и веса настраиваются переменными
`PHOTO_REPO` / `PHOTO_WEIGHT` (по умолчанию `TencentARC/PhotoMaker-V2`).

## Как указать приложению

В `config/providers.json` приложения адрес машины с контейнерами (в файле
уже есть записи под каждую модель с `localhost` — поменяйте host, если
контейнеры на другой машине):

```json
"qwen3-vl-8b": { "adapter": "openai-compatible", "baseUrl": "http://192.168.1.50:8002/v1", "model": "Qwen3-VL-8B-Instruct", "vision": true },
"flux-dev":    { "adapter": "openai-images", "baseUrl": "http://192.168.1.50:8102/v1", "model": "flux-dev" }
```

`localhost` — если контейнеры на том же ПК; IP машины в локалке — если на
другой. Агентам модели назначаются в `config/team.json`: поле `"vision"` —
чем агент смотрит картинки (блок look), поле `"image"` — чем рисует (блок
image), в обоих случаях — id записи из providers.json.

Облачные варианты подключаются так же, без docker: запись с `baseUrl`
облачного API и `apiKeyEnv` (в providers.json уже лежит пример `glm-vision` —
GLM-4.6V через обычный Z.ai-ключ).

## Facade (facade/app.py)

Тонкая обертка над diffusers: принимает наш OpenAI-подобный JSON, возвращает
PNG в base64. Один и тот же код обслуживает все image-модели — список задаётся
переменной `MODELS` в формате `имя=вид:репозиторий` (см. compose):

- `имя=sd-turbo:репо` / `имя=flux-schnell:репо` — быстрые модели
  (шаги/guidance подставляются автоматически: 4 шага, без guidance);
- `имя=flux:репо` — FLUX.1-dev и подобные (28 шагов, guidance 3.5);
- `имя=sd:репо` — прочее SD-семейство (умолчания diffusers);
- `имя=sd-small:репо` — «похудевшие» SD1.5 (BK-SDM и т.п.), 25 шагов;
- `имя=photomaker:репо` — контроль лиц (базовая SDXL-модель в репо, веса —
  в `PHOTO_REPO`);
- `имя=edit:репо` — Qwen-Image-Edit, несколько референсов.

Агент всегда может прислать `steps`/`guidance`/`seed` явно — они перекрывают
умолчания. Переменная `LCM_LORA` (репозиторий LoRA-адаптера, например
`latent-consistency/lcm-lora-sd1.5`) прикручивает LCM: SD-модель генерирует
за 4–8 шагов с guidance 1–2 (умолчания facade — 6 шагов и 1.5). У bk-sdm в
этом режиме не трогайте шаги руками — больше 8 шагов с LCM смысла не имеет.
Включена у контейнера `bk-sdm`; выключается удалением переменной из compose.
На GPU пайплайны работают с offload-ом (компоненты подгружаются на
карту по очереди), поэтому FLUX влезает в карты от ~16 ГБ. Добавить модель =
дописать пару в `MODELS` контейнера. Больше ничего.

## Замечания

- `flux-dev` — gated-модель: на huggingface.co примите лицензию
  black-forest-labs/FLUX.1-dev, затем создайте файл `.env` рядом с compose
  со строкой `HF_TOKEN=hf_...`. Остальные модели свободны.
- Image-провайдеры по протоколу — OpenAI images API, но референсы передаются
  JSON-ом с data:URL (формат нашего facade), а не multipart: заточено под
  свой контейнер.
- CPU-генерация честно медленная: один вариант sd-turbo 512×512 — от десятков
  секунд до пары минут в зависимости от процессора; bk-sdm с LCM — того же
  порядка (UNet втрое меньше, но шагов больше четырёх), без LCM — вдвое-втрое
  дольше. CPU-зрение (2B/4B в Q4) отвечает за секунды.
